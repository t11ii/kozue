# Kozue (梢)

軽快に動く、シンプルで美しいマインドマップアプリ。macOS / Windows 対応。

- **超軽量** — アプリ本体は約 3.4 MB、Web 部分は約 250 kB。依存ライブラリなしの Canvas 描画で、数千〜数万トピックでも滑らかに動きます（約 2 万トピックの再レイアウトが 1〜2 ms）。
- **キーボード中心** — `Tab` でサブトピック、`Enter` で次のトピック。そのまま打ち始めれば編集、日本語入力 (IME) にも対応。
- **6 つのテーマ・12 の構造** — マインドマップ、ロジックチャート (右/左)、ブレースマップ、組織図 (下/上/ツリー)、ツリーチャート、タイムライン (横/縦)、フィッシュボーン (左向き/右向き)。ブランチごとに別の構造にすることもできます（マインドマップの一部だけ組織図にする、など）。
- **書き込む・整理する** — ブランチごとの色、マーカー、ノート、リンク、To-Do、ラベル。トピック同士を結ぶ関連線、ブランチを囲む囲み、隣り合うトピックをまとめる要約。
- **見た目を整える** — トピックごとの形 (角丸・四角・カプセル・楕円・ひし形・下線・枠なし)、塗り・枠線・文字の色、太字・斜体・取り消し線、文字サイズ、幅。「重要」「取り消し」のクイックスタイル、スタイルのコピーと同じ階層への一括適用。マップ全体の背景色・線の太さ・フォント。
- **探す・絞る** — 検索と置換、マーカー・ラベル・To-Do によるフィルター、選んだブランチだけを表示。
- **Xmind からの乗り換え** — `.xmind` の読み込み・書き出し（関連線・囲み・要約・ラベル・ブランチごとの構造・トピックのスタイルも引き継ぎます）。Markdown / OPML / FreeMind も読めます。
- **書き出し** — PNG / JPEG / SVG / PDF / Markdown / テキスト / OPML / Xmind。画像は倍率 (1x〜3x)・背景の透明化・ブランチ単位・メインブランチごとの分割を選べます。

## 使う

### macOS アプリ

```sh
npm install
npm run app:build        # → src-tauri/target/release/bundle/macos/Kozue.app (+ .dmg)
```

できあがった `Kozue.app` を「アプリケーション」フォルダへ。`.kozue` ファイルのダブルクリックでも開けます。

### Windows アプリ

Windows 上で同じコマンドを実行します（[Rust](https://rustup.rs/) と Node.js、Visual Studio の「C++ によるデスクトップ開発」が必要）。

```sh
npm install
npm run app:build        # → src-tauri\target\release\bundle\nsis\Kozue_0.1.0_x64-setup.exe
```

手元に Windows の開発環境がなければ、このリポジトリを GitHub に push して Actions の **build** ワークフローを実行すると、
macOS (.dmg) と Windows (.exe / .msi) のインストーラーが成果物としてダウンロードできます
（[`.github/workflows/build.yml`](.github/workflows/build.yml)）。

> 署名していないビルドのため、初回起動時に macOS では「右クリック → 開く」、Windows では SmartScreen の「詳細情報 → 実行」が必要です。

### インストール不要の単一 HTML 版

```sh
npm run build:html       # → standalone/Kozue.html (約 250 kB)
```

`Kozue.html` をダブルクリックするだけで、Chrome / Edge 上でそのまま動きます（Windows でも macOS でも同じファイル）。
Chrome / Edge ではファイルを直接開いて `Ctrl/⌘+S` で上書き保存できます。Safari / Firefox では保存がダウンロードになります。

## キーボードショートカット

`⌘` は Windows では `Ctrl` です。アプリ内のメニュー →「キーボードショートカット」でも確認できます。

| 操作 | キー |
| --- | --- |
| サブトピックを追加 | `Tab` |
| トピックを追加（後 / 前） | `Enter` / `Shift+Enter` |
| 親トピックを挿入 | `⌘+Enter` |
| テキストを編集 | `Space`・`F2`・ダブルクリック・そのまま入力 |
| 編集中に改行 | `Shift+Enter` |
| 削除 | `Delete` / `Backspace` |
| トピック間を移動 | 矢印キー |
| 順序を入れ替え / 階層を上げ下げ | `Alt+↑↓` / `Alt+←→` |
| 折りたたむ / 展開 | `⌘+/` |
| 複製 / 元に戻す / やり直す | `⌘+D` / `⌘+Z` / `Shift+⌘+Z` |
| To-Do にする・チェックする | `Shift+⌘+D` |
| 関連線 / 囲み | `Shift+⌘+L` / `Shift+⌘+B` |
| リンク / ノート | `⌘+K` / `Shift+⌘+E` |
| クイックスタイル「重要」/「取り消し」（もう一度で解除） | `Shift+⌘+1` / `Shift+⌘+2` |
| 太字 / 斜体 / 取り消し線（編集中も可） | `⌘+B` / `Shift+⌘+I` / `Shift+⌘+X` |
| スタイルをコピー / ペースト | `⌥+⌘+C` / `⌥+⌘+V`（Windows は `Ctrl+Alt+C` / `Ctrl+Alt+V`） |
| 検索 / 検索と置換 | `⌘+F` / `⌥+⌘+F`（Windows は `Ctrl+H`） |
| 選んだブランチのみ表示（もう一度で戻る） | `⌘+;` |
| 拡大・縮小 / 100% / 全体表示 | `⌘+=`・`⌘+-` / `⌘+0` / `⌘+1` |
| フォーマットパネル | `⌘+I` |
| 新規 / 開く / 保存 / 別名で保存 | `⌘+N` / `⌘+O` / `⌘+S` / `Shift+⌘+S` |

マウス・トラックパッド: スクロールで移動、ピンチまたは `⌘+スクロール` で拡大縮小、余白ドラッグで移動、
`Shift+ドラッグ` で範囲選択、トピックのドラッグで付け替え、右クリックでメニュー。
選択したトピックの左右の端をドラッグすると幅を変えられます（端のダブルクリックで文字に合わせた幅に戻ります）。

関連線・囲み・要約は、ツールバーの「サブトピック」の右に並ぶ 3 つのボタンからも入れられます。

- **関連線** — トピックを 1 つ選んで実行し、つなぐ先をクリック（2 つ選んでいればすぐにつながります）。線はドラッグで曲げられ、選択中に `Enter` で文字を添えられます。
- **囲み** — 選んだブランチ全体を枠で囲みます。タイトルはフォーマットパネルで付けます。
- **要約** — 同じ親の、隣り合ったトピックを選んで実行すると、括弧でまとめた先に要約トピックができます（タイムラインとフィッシュボーンの軸の直下では括弧にならず、通常のトピックとして並びます）。
- **ブランチの構造・ラベル・To-Do・フィルター** — フォーマットパネル (`⌘+I`) から。
- **スタイル** — フォーマットパネルの「スタイル」タブ、または右クリックメニューの「スタイル」から。複数のトピックを選んでまとめて変えられます。
  形に「A」（テーマに合わせる）以外を選ぶか、塗り・枠線の色を付けると、下線だけのサブトピックも箱になります。
  「同じ階層のトピックに適用」は、選んだトピックのスタイルをマップ内の同じ深さのトピックすべてに写します。
- **マップの設定** — 「マップ」タブで背景色・線の太さ・フォント (ゴシック / 明朝 / 丸ゴシック / 等幅) を変えられます。テーマを選び直すと、背景色はそのテーマのものに戻ります。

## ファイル形式

`.kozue` は読みやすい JSON です（Git での差分管理にも向いています）。

```json
{
 "format": "kozue",
 "version": 1,
 "theme": "hinata",
 "layout": "map",
 "root": {
  "text": "中心トピック",
  "children": [
   { "text": "計画", "side": "r", "color": 0, "id": "t1", "todo": false, "labels": ["今週"] },
   { "text": "実行", "side": "r", "color": 1, "structure": "org", "boundary": "チーム" },
   { "text": "ここまでが前半", "side": "r", "color": 2, "summary": 2 },
   { "text": "振り返り", "side": "l", "color": 3, "id": "t2",
     "style": { "shape": "ellipse", "fill": "#ffe08a", "bold": true }, "width": 160 }
  ]
 },
 "style": { "background": "#fdf6e3", "line": 1.6, "font": "serif" },
 "relationships": [{ "from": "t1", "to": "t2", "text": "次に活かす" }]
}
```

`structure` はそのブランチだけの構造、`boundary` は囲みのタイトル（空文字ならタイトルなし）、`summary` は直前の何個のトピックを要約するか、
`id` は関連線の両端になるトピックにだけ付きます。

トピックの `style` に書けるのは `shape` (`rounded` / `rect` / `pill` / `ellipse` / `diamond` / `underline` / `none`)、`fill`（`#rrggbb` または塗りなしの `none`）、
`border`・`color`（`#rrggbb`）、`bold`・`italic`・`strike`、`size`（px）で、書かなかった項目はテーマに従います。`width` は手で決めた文字の幅 (px) です。
いちばん外側の `style` はマップ全体の設定で、`background`（背景色）、`line`（線の太さ。1 が標準）、`font`（`serif` / `round` / `mono`）を書けます。

保存していない変更は自動的に控えられ、次回起動時に復元されます。

## 開発

```sh
npm run dev          # ブラウザで開発 (http://127.0.0.1:1420)
npm run app:dev      # デスクトップアプリとして開発 (Tauri)
npm test             # ユニットテスト (Node のテストランナー、追加の依存なし)
npm run typecheck    # 型チェック
npm run format       # Prettier
```

デスクトップ版のスモークテスト: 環境変数 `KOZUE_SELFTEST=<出力先フォルダ>` を付けてアプリを起動すると、
実際の WebView 上で編集・保存・読み込み・全構造のレイアウト・関連線や要約などの描画・全形式の書き出しを自動実行し、`report.json` を出力して終了します（成功時の終了コード 0）。
テストは専用の一時的なデータストアで動くので、ふだん使っているセッション（下書きや設定）には触れません。

```sh
KOZUE_SELFTEST=/tmp/kozue-test src-tauri/target/release/bundle/macos/Kozue.app/Contents/MacOS/kozue
```

### 構成

```
src/
  core/      データモデル (Undo/Redo つきの木構造)・テキスト折り返し・レイアウト・構造の定義・テーマ
  render/    描画。Canvas と SVG の 2 つのバックエンドを同じコードで駆動
  app/       選択・編集コマンド・アニメーション・入力処理・ファイル管理
  io/        ファイル形式 (Markdown / OPML / FreeMind / Xmind / ZIP / PDF)
  ui/        ツールバー・メニュー・パネル・ダイアログ
  platform.ts  デスクトップ (Tauri) とブラウザの差異を吸収
src-tauri/   デスクトップ用シェル (Rust)。ファイル入出力・ウインドウ・macOS メニュー
tests/       ユニットテスト
scripts/     単一 HTML 版のパッケージング
```

構造 (structure) の仕組み: 各トピックは「子をどう並べるか」を表す配置コード (横に積む / 下に並べる / インデントして並べる / 軸に沿う / 骨に吊るす…) を持ち、
構造はその組み合わせのルールとして `src/core/structures.ts` に定義されています。レイアウト・接続線の描画・矢印キーの移動・ドラッグ先の判定はすべて
配置コードに対して書かれているので、新しい構造はルールの追加が中心になります。配置は子ブランチ全体の広がりだけを見て決めるので、
どの構造の中にどの構造を入れても重なりません（囲みは広がりを一回り大きくするだけ、要約はまとめるトピックの隣に置くだけで実現しています）。

軽さのための設計:

- 画面は 1 枚の Canvas。表示範囲外のブランチは部分木ごと描画をスキップし、縮小時は文字を簡略表示します。
- レイアウトは毎回 O(表示中のトピック数)。文字幅の計測は内容が変わったトピックだけ。
- 接続線は色と太さごとに 1 つのパスにまとめて描画します。
- フレームワークやランタイム依存はありません（開発時の Vite / TypeScript と、デスクトップ化の Tauri のみ）。

## いまの制限

- ブランチの構造にマインドマップ（左右に広がる形）は選べません。マインドマップは中心トピック専用です。
- 囲みは 1 つのブランチ単位です。Xmind で複数のトピックをまとめて囲んだ枠は、読み込むとトピックごとの枠になります。
- 関連線の曲がり具合は Xmind との間で引き継ぎません（つながりと文字は引き継ぎます）。
- Xmind との To-Do・スタイルのやり取りは、実際の Xmind アプリでは未確認です（ファイル形式の知識に基づく対応付けです）。
- Xmind から読み込むスタイルは、トピックに直接指定されたものだけです。Xmind のテーマが与えている見た目や、Kozue にない形（雲・六角形など）は引き継がず、Kozue のテーマに従います。
- スタイルはトピック全体に付きます（文字の一部だけを太字にする、などはできません）。枠線の太さと、ブランチごとの線の形・太さは変えられません。
- 丸ゴシックなどのフォントは、その OS に入っている書体で表示します（Windows には丸ゴシックの標準書体がないため、近い書体になります）。
